# Bolna live setup and first proof

1. Deploy web and worker using DEPLOYMENT.md. Use a public HTTPS APP_ORIGIN and Supabase Auth; local auth deliberately cannot place real calls. Set SESSION_SECRET to at least 32 random bytes and independent random BOLNA_TOOL_SECRET and BOLNA_WEBHOOK_SECRET. Keep these on the server and in Bolna's private tool/header settings only.
2. In the Bolna account create two conversation agents: conductor and phone. Set BOLNA_CONDUCTOR_AGENT_ID and BOLNA_PHONE_AGENT_ID from their actual ids; set BOLNA_API_KEY. Configure voices/languages available in the account. Use the prompts in this directory. The phone agent must introduce itself as AI, have provider-side maximum duration equal to MAX_CALL_SECONDS, and have all automatic call retries disabled. Never enable purchase/reservation or transfer tools.
3. Import the generated role-specific function definitions from generated/. Replace YOUR-HTTPS-HOST and the tool-secret placeholder in the dashboard. Keep conductor functions off the phone agent. Keep the prompt context variables exactly named as provided, including chorus_token. CHORUS sends user_data; verify Bolna substitutes it into `%(chorus_token)s`. The backend also accepts direct structured JSON for local contract tests.
4. In the phone agent's Extractions/Webhook Configuration set `https://YOUR-HTTPS-HOST/api/bolna/webhook`, all statuses, Add headers: `x-chorus-webhook-secret: <your secret>`. These are custom shared-secret headers; CHORUS does not claim provider-signed webhooks. Bolna documents source IPs 13.203.39.153, 13.126.9.249, 13.202.133.53; optionally restrict at a trusted ingress. Do not trust caller-supplied forwarded IP headers for authentication.
5. Obtain explicit authorization from each participant and a separate maximum call-cost budget. Set CALL_ALLOWLIST to only their E.164 phone numbers. Verify actual ACCOUNT_CONCURRENCY (including conductor); use 2 for one phone call + browser or at least 4 for three phone calls + browser. Set a calling window and IANA zone, MAX_CALLS_PER_MISSION and a conservative CALL_COST_RESERVE_MINOR for the full maximum call duration. A mission's INR event budget is separate from telephony authorization. Reserves are conservative and not automatically refunded.
6. After verifying provider duration caps, pricing, concurrency and disabled retries, set LIVE_AGENT_LIMITS_VERIFIED=true, SIMULATION_ONLY=false, ENABLE_REAL_CALLS=true and AUTH_MODE=supabase. This alone does not dial: create a real mission, enter an allowlisted participant in Contacts and mark their authorization. Then approve a current research card and a call-cost amount. Increase the per-mission cap deliberately if testing repeated budget revisions; the default six attempts may stop a long rehearsal.
7. **Browser proof:** create a draft real mission, Talk to conductor. Ask it to read the current budget with get_mission_brief. Ask it to change budget to INR 9,000. Confirm a persisted revision and stale previous proposal in the UI and database. Record the actual run/execution id and timestamp in VERIFICATION.md. Stop browser voice to release the session.
8. **One outbound proof:** keep only one authorized task eligible (other tasks without authorized contacts fail closed); approve research and telephony budget. Ask participant to report a structured availability, setup duration or offer. Confirm phone get_mission_brief and report_observation or submit_offer reach the backend, source attempt matches execution id, and callback/polling reaches completed. Record actual ids and evidence, never label a mocked HTTP response as live proof.
9. Only after those pass, test three authorized participants concurrently. Venue offers access at 17:30; catering reports 45-minute setup; venue refreshes brief and investigates access before 17:15. While active, speak the INR 9,000 revision; agents reconfirm terms after a current brief read. If they cannot meet it, the expected result is blocked.

Recovery: a timeout on POST /call marks the attempt uncertain and occupies concurrency. Inspect provider call history. Enter the matching execution id in the uncertain card; CHORUS fetches it and checks agent and recipient before associating it. If provider history cannot resolve it, leave the attempt uncertain and use Bolna support; do not blindly redial. Pause attempts queued cancellation and blocks new admission; active termination is not promised.

Credentials and participant authorization are currently missing. These steps have been prepared, not executed live.
